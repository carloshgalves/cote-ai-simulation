# LLM Evals

Maintain versioned golden scenarios. Record model/provider/version, prompt/context-builder version, temperature/configuration, dataset version and repeated-run count.

Evaluate dimensions relevant to this simulation:
- decision plausibility;
- strategic competence;
- adherence to available knowledge;
- action-schema validity;
- stable refusal/uncertainty when evidence is absent;
- latency and estimated cost.

Compare baseline and candidate on the same cases. Do not accept a candidate solely because average quality improves if it introduces a severe fidelity or knowledge-leak regression.

Expected answers/rubrics must not be generated by the same model under test and blindly treated as ground truth.

## Mandatory CI billing/runner fallback

When CI does not allocate runners or cannot execute, follow `docs/agents/ci-billing-fallback.md` and `AGENTS.md`: check runner/steps before diagnosing financial cause; report `CI_NOT_RUN` separately from failed code/evals, run bounded local deterministic/replay/eval verification with real exit codes and protected corpus excluded, and preserve separate human phase and merge gates.
