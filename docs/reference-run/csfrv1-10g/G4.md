  physical epochs, under a registered interpreter/module/import tree and a
  Genesis-bound Ed25519 signing key. The Go verifier independently checks
  the exact immutable source hashes, completed-state/A2 digests, source ID,
  run, Genesis and epoch before physical ingress.
- D2 stages both signed inputs into the real SQLite InputLedger and commits
  two `physical.advanced` engine-only events under the **Go** AdmissionFence,
  physical reducer and clock authority. C4 resource/communication history
  survives: 9 revisions, Go instant 35, 2 physical epochs, stable resource
  ownership, continuous body state, replay, snapshot and final SourceClosure.
- D3 audits actual persisted event/task/evidence routes and actor A/B and
  public Observatory access. No ordinary PerceptionTask or public route may
  refer to the physical engine events. An altered route, event or outbox
  fails the auditor; a privileged body/seed is not a public certificate.
- In a controlled experiment, **the exact two authenticated Python cuts**
  are reused in two independent complete D3 runs with source/response
  order reversed. Compare both cognitive owner DBs, all canonical
  ledger rows and terminal IDs by the E1 byte oracle. Fresh Python
  executions are *not* byte-equivalent inputs because `wall_time` is
  genuine source provenance. Neither Python wall_time nor its local
  `seq` determines global Go `SimulationInstant` or logical sequence.
- Mutating any signed source field (run/Genesis/source, executable,
  snapshot/event/A2/body hashes or epoch) or Ed25519 signature with
  a **shape-valid canonical payload** is denied against the positive
  registered source control. Installing a *different valid policy/key*
  while reusing the original genuine source cuts also fails before
  physical WorldRevision/CycleCommit/Event publication. D2 already
  tests executable/import-tree damage, wrong epoch and foreign RunID.
