## Outcome contract — G6 is a final **audit/disposition**, not automatic acceptance

All four registries (simulation, determinism, embodiment, knowledge) remain `SCOPED_WITH_GAPS`, with 109 normative requirements (41 INV + 68 STRESS). Prior registration states at the base are **51 READY**, **50 NOT_RUN**, **8 BLOCKED**. READY is a witness registration, not an observed test PASS. `NO_GO_INCOMPLETE_MATRIX` remains the only honest outcome if all the 51 registered lines pass while the other 58 remain unproven. The runner never silently promotes an unsupported row or treats a green CI as release authorization.

Actual G6 job, all at one **clean exact commit SHA**:

1. The pinned Python 3.13 A1 producer creates real Go input fixtures; G2, G3, G4 and G5 focused checks run with uncached Go tests and `-race` where configured.
2. The original `run_evals.py` executes **every unique witness normal and `-race`**, including its declared subtest inventory, validates Go event histories and writes a 109-row `evidence.json`. Timeouts, skips and missing subtest events remain failures; the sole already reviewed 25m race exception is `g3-e2-physical-atomic/race`.
3. Within **that same GitHub Actions job / source SHA**, the independent Go CSF V1 conformance runner and TypeScript runner execute the normative **621 cases**. G6 checks literal byte equality of the two reports, pinned suite hash, all fixture-derived unique IDs **in exact order**, per-case PASS and 621/621 totals.
4. `g6_finalize.py` independently checks the G1–G5 evidence against the source SHA and registry blob, both frozen source identities and exact witness source blobs. It **reopens the private uncached original JSONL/stderr logs**, verifies their hashes, replays the same Go `start/run/pass` inventory and compares sanitized records byte-for-byte. It recomputes all row/eval statuses (it does not accept self-reported green counters) and verifies the current CI invocation. If conformance, raw tests or ownership contradict the current tree, certification fails.
5. On internally consistent results G6 emits two **minimal, public-safe** certificates: `g6-decision.json` (counts, conformance SHA256, four eval scope states, named external review gates, exact commit, no GO) and `g6-gaps.json` (one entry for each BLOCKED/NOT_RUN/FAIL normative ID with owner, documented reason, blocker and follow-up issue). **Raw Go logs, canonical data, owner secrets and full conformance case vectors are not uploaded**; they remain inside the ephemeral private runner.

The digest-only artifacts are uploaded by `.github/workflows/csfrv1-10g-evals.yml`. The G6 certificate is not signed externally and does not overstate trust in the CI checkout, runner image or source-code attestations. A GitHub **CI_NOT_RUN** (no runner/steps) is neither PASS nor failing domain code. `NO_GO_FAILED_EVIDENCE` is distinct from an all-green but incomplete `NO_GO_INCOMPLETE_MATRIX`; even if all 109 rows became locally green, the scopes and external reviews would still block production approval.

## Commands / reproducibility

On a clean Linux checkout, Go 1.27.2, Python 3.13.18, Node 22, and the A1 dependencies pinned in the workflow:

```sh
python -B docs/reference-run/csfrv1-10g/test_run_evals.py
python -B docs/reference-run/csfrv1-10g/test_g6_finalize.py
python -B docs/reference-run/csfrv1-10g/run_evals.py \
  --sha "$(git rev-parse HEAD)" --out /tmp/g6-fresh-evidence
go run ./cmd/csf-harness \
  --bundle docs/architecture/canonical-codec-v1-bundle \
  --report /tmp/g6-fresh-evidence/g6-go-v1-report.json
node --no-warnings --experimental-loader ./tools/csf-conformance-ts/loader.mjs \
  tools/csf-conformance-ts/runner.ts \
  docs/architecture/canonical-codec-v1-bundle \
  /tmp/g6-fresh-evidence/g6-ts-v1-report.json
cmp /tmp/g6-fresh-evidence/g6-go-v1-report.json \
  /tmp/g6-fresh-evidence/g6-ts-v1-report.json
G6_NODE_VERSION="$(node --version)" python -B docs/reference-run/csfrv1-10g/g6_finalize.py \
  --sha "$(git rev-parse HEAD)" \
  --evidence /tmp/g6-fresh-evidence/evidence.json \
  --go-report /tmp/g6-fresh-evidence/g6-go-v1-report.json \
  --ts-report /tmp/g6-fresh-evidence/g6-ts-v1-report.json \
  --out /tmp/g6-fresh-evidence
```

`/tmp/g6-fresh-evidence` is an example **fresh unique external directory**. G6 uses the original source logs written there, not copied or summarized evidence from a previous SHA or job.
