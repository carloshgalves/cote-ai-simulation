**Parent:** H2 #177 / H #122, based on the human-merged H2-R [PR #180](https://github.com/carloshgalves/cote-ai-simulation/pull/180) (`main@b1099a3e086f874f15d6c6fc49a70986d1531c70`).

## What is proven (only after exact-SHA CI is green)

The original real Python A1 supervision runs twice for the **first** C4/D2/D3. Its two original `snapshot.yaml`, `events.jsonl`, `evidence.json`, `cut.cbor` and `signature.bin` files are retained under the host-owned 0700 `physical-cuts/` directory, with signer secret **never exported**. Each original file is checked by the signed A1 epoch, installed Genesis/manifest and registered Ed25519 public key, A2 replay on freshly sealed Linux memfds, and exact canonical InputLedger source ingress.

Then a **second, independent** fresh `replay/causal.db`, `replay/owner/actor-b.db.actor-a`, `replay/owner/actor-b.db` is generated by calling the same actual Go C4/D2/D3 runner, **without running Python a second time**. A deliberately separate, explicitly named offline reference entry point in the `internal/csf/commit` package reconstructs two non-recovered ApprovedCuts from the SAME first run's original raw bytes, only after checking their full Genesis-bound Ed25519 signatures, typed completed states, and freshly sealed A2 validation. Normal production-like `RunReferenceD3` continues to call the genuine Python supervisor and is unchanged. This offline entry point is not offered as a simulated actor input/admission API, and the second runner never updates or overwrites the first SQLite authority. A recovered post-crash `ApprovedCut` remains terminal-only and cannot be used as new ingress.

The cold verifier requires both primary and independent DB trees, cross-checks both reconstructed Genesis and `ReplayClock`, verifies both C4 sealed snapshots + 3 tail commits and both pairs of signed private owner ACKs, and then **re-reads every SQLite table** from each causal/owner DB. It compares exact table name+DDL, ordered column identity, row **multisets** with typed cell tags (blob/text/int/real/null) and SHA-256 of complete row content. Duplicate records retain multiplicity; different insertion order or SQLite page/WAL layout is irrelevant. It verifies the two runs' public D3 reports byte-identically, including the same 2 signed A1 input identities. The summary `replay/compare.json` contains only counts and hashes — no private actor bodies or raw physical source. No private archive is uploaded to GitHub or exposed as an Actions artifact.

The operator's `checksums.json` inventory now covers both full independent causal databases, the four original & second private owner DBs, the original raw A1 archive, five canonical ledgers, original receipts and the signed-source proofs; optional WAL/SHM for second DBs are indexed when present. New archives declare `run-manifest.evidence_profile=H2_SAME_A1_REPLAY_V1` and missing/malformed second DBs or proof fails closed. H1/H2-L/H2-S/H2-R legacy archives retain their **narrower** verification and are never promoted to H2-I.

## Adversarial checks and hard limits

Real-run CI normal and `-race` replays the same signed A1 sources into fresh Go DBs, runs a detached verifier without Python, and requires all tables/owners/canonical reports equal. Mutants with entirely recalculated local SHA-256 indexes must reject changed original physical inputs, owner checkpoints, causal ledger rows, extra replay table and tampered comparison report. A malformed/unsigned or wrong-epoch A1 pair must refuse **before opening a second SQLite authority**.

This proves **two independent causal executions of the same input pair**. It does *not* prove that a different fresh Python capture with its own genuine `wall_time` would be byte-identical; comparing fresh A1 captures would be logically incorrect. It also does not mean source attestation on a separate host, immutable external auditor anchor, or production authorization: the second replay uses the same installed policy and trusted local signer from RAM, and files are still operator-owned. Whole-package rollback including changed manifest profile is not prevented by local checksums alone.
